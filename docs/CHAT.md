# 基础角色会话

## 范围

0.2.6 基线对应用户需求：右键角色，在角色下方打开已聚焦的会话输入窗口；Enter 发送，Shift+Enter 换行；通过一个会话设置入口配置网站、API key、角色人设和最长回复长度；角色回复使用自动增长的气泡，并支持 stream。此后开发的主动闲聊与番茄钟见 [独立说明](COMPANION-ACTIVITY.md)。插件操作和用量提示改写仍未接入。

会话设置还包含可编辑的模型名称。DeepSeek 官方 V4.1 Flash 使用 `deepseek-flash`，API 地址填写 `https://api.deepseek.com`；新配置以此模型名为默认值。接口支持兼容 Chat Completions 的 HTTPS API，也支持本机 HTTP 服务。地址可填写 API 根路径（例如 `/v1`）或完整 `/chat/completions` 地址，不可填写聊天网站的普通网页地址。

最长回复长度是请求的 `max_tokens`，默认 1024；范围 1 到 32768，实际可用上限由模型决定，不是字符数。主动闲聊和番茄钟提醒另有“主动消息最长回复”，见[独立说明](COMPANION-ACTIVITY.md)。角色人设作为 system 消息，最近完整的对话作为上下文；中断、失败及取消的回复保留在记录中，但不进入后续模型上下文。首版显示纯文本。

每次发出聊天请求时，后台读取设备本地日期、时间、星期和时区，作为临时 system 消息提供给模型。角色可以据此自然调整话题和建议，无需每轮报时；时间上下文不写入会话记录，也不代表挂件知道用户正在做什么。自动闲聊和番茄钟提醒同样在生成时重新取时。

## 模块

| 模块 | 职责 |
| --- | --- |
| `runtime/chat/service.mjs` | 会话配置、密钥引用、历史、前台与后台回复的调度和取消 |
| `runtime/chat/reply.mjs` | 生成一次回复：组装人设、本地时间与历史，处理工具调用（之后最多再发两次模型请求），每个模型请求单独记账，超时与错误说明；不写历史 |
| `runtime/chat/conversations.mjs` | 会话列表、当前会话、独立消息存储、旧历史迁移与原子保存 |
| `runtime/chat/time-context.mjs` | 为当次模型请求构建设备本地时间上下文 |
| `runtime/chat/provider.mjs` | 兼容 Chat Completions 的请求与 SSE 模型响应转换 |
| `runtime/chat/billing.mjs` | 独立会话计费记录、30 天统计、官方余额查询及缓存 |
| `runtime/chat/deepseek-pricing.mjs` | 用量验证、缓存命中与峰谷价格估算 |
| `desktop/ui/chat-client.js` | 调用本地会话路由、消费流式事件 |
| `desktop/ui/chat.js` | 输入、会话设置、记录、生成与停止状态 |
| `desktop/ui/chat-billing.js` | 发送按钮旁的消费、余额、刷新与错误状态 |
| `desktop/ui/companion-display.js` | 在角色周围定位输入窗口与回复气泡，随内容增长并限制在视口内 |
| `lib/event-stream.js` | 前后台共用的 SSE / UTF-8 流读取；页面经 `/lib/event-stream.js` 加载 |

`companion-display` 通过传入的 DOM 和 `open / close / show / update / append / hideReply` 工作，不读取用量、账本、密钥或模型配置。`update` 用于后台记录恢复，保留用户收起气泡和滚动的位置。与已有宠物代码只通过打开、位移和回复显示事件装配。已有审批气泡可以覆盖会话回复，结束后会话回复恢复，生成过程继续。

回复气泡随内容向上增长，达到可用高度后内部滚动。桌面底部没有输入空间时，角色上移腾出下方空间；顶部没有足够回复空间时，回复靠角色侧边显示。窄屏侧边空间不足时，角色下移腾出顶部回复空间。窗口跟随角色移动，输入窗口不跟随角色镜像翻转。

## 本地接口与存储

- `GET /api/chat/settings`：非敏感配置、`hasKey` 和密钥存储方式。
- `PUT /api/chat/settings`：保存配置；key 留空保留已保存值。更换网站域名须提供新网站 key。
- `GET /api/chat/history`：当前会话及生成标识。
- `DELETE /api/chat/history`：兼容旧入口，删除当前会话，计费保留。
- `GET /api/chat/conversations`：会话摘要列表和当前会话 ID。
- `POST /api/chat/conversations`：新建并切换到空会话，保留已有会话。
- `PUT /api/chat/conversations`：`{ id }`，切换到对应会话。
- `DELETE /api/chat/conversations`：`{ id }`，删除指定会话，计费保留；删除当前会话时切换到最近会话，全部删除后创建空会话。
- `POST /api/chat/message`：`{ id, text, conversationId }`，以 SSE 返回 `start / delta / done`；`done` 包含最终状态和已观测 token。会话 ID 过期时拒绝发送，避免切换期间将文字发送到错误上下文。
- `POST /api/chat/stop`：`{ id }`，停止对应生成。
- `GET /api/chat/billing`：当前会话密钥的滚动 30 天消费估算、已计费／待核调用数和账号余额；`?refresh=1` 刷新余额。

网络请求在桌面后台发出，渲染页面只连接本地路由。API key 不回显、不写入设置或历史、不进入错误提示；禁止自动跟随重定向。macOS 使用已有 Keychain / Electron safeStorage 加密存储；当前其他环境不持久化 key，只保留在进程内，设置窗口会显示存储方式。

密钥更新使用两个加密引用槽，配置中的 `keyRef` 与 API 地址一起原子保存，提交后才切换当前密钥。首次配置、同域更新及跨域切换保存失败时，不会启用新 key 或将它发送给旧网站。内存存储同样在配置保存成功后才更新。

配置为 `chat-settings.json`，会话为 `chat-history.json`，只保存此功能产生的内容；不会把 Codex 会话内容用于聊天。历史文件版本 2 保存多个独立会话和当前会话 ID；旧的单会话记录自动迁入首个会话，并首次备份为 `chat-history.v1.json`。每个会话最多保留 60 轮 / 约 512 KiB，上下文最多 20 个已完成轮次且另有长度限制，互不混用。聊天不调用现有 Codex 轮次计费入口，不改变原有账本。

macOS 可用全局 Ctrl+0 打开会话并聚焦输入框；挂件托盘菜单也有相同入口。此快捷键会抢占 Excel 等应用中的 Ctrl+0 操作；若系统已有全局占用，托盘菜单会提示注册失败，菜单入口仍可使用。

macOS 原生输入法同时依赖应用激活和原生窗口焦点，不能只检查 `textarea` 的 DOM 焦点或缓存的编辑状态。用户打开会话或点击可输入区域时，后台激活桌面应用并恢复窗口焦点；会话已经打开、切到其他应用后再次按 Ctrl+0 也会重新检查原生焦点。自动番茄钟提醒仍不请求键盘焦点。相关平台接口见 [Electron app.focus](https://www.electronjs.org/docs/latest/api/app#appfocusoptions)。

输入框上方的“列表”可打开会话列表，标题取首条消息。点击列表项恢复消息并继续聊天，切换时保留本次运行中的输入草稿；“新会话”建立新的空会话。删除按钮需在对应条目再次点击“确认删除”。生成期间不能新建、切换或删除会话。删除及切换均原子保存，保存失败保持原有会话选择。

首次回复 / 流中无有效输出 60 秒超时，一次生成最长 180 秒；停止或连接中断时保留已收到文本。回复不自动关闭；点击回复气泡任意位置可收起，展开“记录”会再次显示当前会话最后一条有文本的回复；手动收起后，后续流式输出和重复按 Ctrl+0 都不会强制将它重新展开。

## 独立会话计费

发送按钮左侧显示“本地30天约”和账号余额，并提供刷新按钮。打开会话、保存设置和回复结束时查询；正常余额查询有 60 秒缓存，回复结束会使缓存失效，手动刷新也会重新查询。查询失败保留旧余额并标记为旧值，计费故障不阻止发送或流式回复。

余额调用官方 `GET https://api.deepseek.com/user/balance`，沿用会话 key，使用 `total_balance`（有效赠金与充值余额之和）。余额属于整个 DeepSeek 账号，不是单独聊天模块的额度；优先显示 CNY，账号返回 USD 时使用其原始币种，不借用 Codex 的显示币种或汇率。只有会话地址的 origin 为 `https://api.deepseek.com` 时才查询此接口；不对第三方中转 key 调用 DeepSeek 官网。

公开 API 文档没有提供账号近 30 天消费明细查询接口。这里仅统计当前网站与当前 key 对应的本地聊天调用，不包含其他应用或已删除的旧调用，因此可能与官网账号消费不同。缺失账本时会恢复已保存的历史用量：旧历史没有账号标识，只恢复当前配置保存之后、近 30 天内的调用；已有账目不重复导入，也不会改归到另一个 key。读取消费、清空历史、保存设置及发送新消息前均执行恢复，避免历史被清空或裁剪后丢失已知用量。更换 key 时各自统计，重新使用旧 key 可以看到其仍在 30 天范围内的记录。`chat-billing.json` 与聊天历史独立，清空聊天不清空消费；记录仅含密钥哈希标识、调用 ID、时间、模型、token 与价格快照，不保存 key 或消息正文。

金额来自流式响应的 `usage`，明确标为“约”，不是官方逐请求账单。请求开启 `stream_options.include_usage`，保留缓存命中、未命中及输出 token；思考 token 已包含在输出 token 中，不另加一次。无完整用量的停止、断线和失败调用标记待核，收到用量的失败回复仍计入消费，未返回费用时不按文字长度猜测，也不把整个账号的余额差值算成聊天消费。

截至 2026-09-27 的 Flash 高峰单价（每百万 token）：CNY 缓存命中 0.04／未命中 2／输出 8，USD 0.006／0.3／1.2；空闲时段减半。按请求开始时间计算，北京时间工作日 9:00–12:00、14:00–18:00 为高峰，周末及已核对的 2026 年放假日期为空闲；跨时段长请求和后续官方调价仍以官方账单为准。缺少缓存明细、或后续年份工作日高峰窗口的节假日尚未核对时，内部保留估算上下限；消费文字显示 `(下限 + 上限) / 2` 并固定为两位小数，不再显示区间，低于显示精度的金额可能显示为 0.00。每次估算连同价格版本保存，后续更改价格不会重算已记录消费。

参考：[官方余额接口](https://api-docs.deepseek.com/api/get-user-balance/)、[中文价格表](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[美元价格表](https://api-docs.deepseek.com/quick_start/pricing/)、[2026 年放假安排](https://www.beijing.gov.cn/fuwu/bmfw/sy/jrts/202511/t20251104_4258838.html)。

## 验证入口

`npm test`、`npm run check`、`npm run test:desktop`。模型、key 和响应均使用合成测试数据，不消费真实额度。桌面验证覆盖右键焦点、Enter / Shift+Enter、气泡增长、停止后继续会话、设置与历史重启持久化，以及原有用量和审批提醒。

macOS 可用 `node scripts/smoke-desktop.mjs --input-focus` 单独快速验证应用激活、聊天框已有 DOM 焦点时原生窗口失焦、再次按 Ctrl+0 恢复原生焦点。这些断言也在完整桌面验证中执行；输入法的实际组词和候选窗需要用原生按键验证，直接插入中文字符不能替代这一步。

2026-09-28：修复编辑状态缓存导致原生窗口失焦后不重新取得焦点，以及桌面应用未激活的问题。用户已使用实体键盘确认 macOS 中文输入法恢复正常。

2026-09-27 验证结果：50 项回归测试通过，84 个 JavaScript 文件及相关源码检查通过。macOS 15.6 / Electron 44.3.0 的真实桌面初次运行和进程重启测试通过，渲染错误为 0。额外覆盖流连接截断后的记录同步、手动收起后不强制展开、1024×768 与 390×844 原生窗口顶部和底部布局、会话列表与记录展开后窗口与角色不重叠、会话消费和余额自动刷新与重启恢复；历史计费恢复覆盖缺失账本、去重、密钥归属和删除会话前保留用量。会话列表覆盖旧数据迁移、独立上下文、草稿恢复、光标恢复、继续旧会话、确认删除、保存失败保护及删除后计费不变。用户已确认真实聊天接入正常；自动测试使用合成用量与余额，不读取用户密钥。
