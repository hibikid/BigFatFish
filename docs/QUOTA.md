# 额度管理

大肥鱼要看的额度都是**额度账户**，由后台的额度簿（`runtime/quota/book.mjs`）统一汇总。挂件下方的进度条、▾ 展开的全部额度、额度管理窗口和 MCP 工具都只读额度簿的结果，自己不判断该显示什么。决定见 [ADR 0002](adr/0002-one-quota-book.md)。

## 四类额度

| 账户 | 数据从哪来 | 显示 |
| --- | --- | --- |
| Codex 订阅 | 本机 Codex 会话记录里的 `rate_limits` 快照（只读窗口、已用比例和重置时间） | 5 小时、7 天剩余 |
| Claude 订阅 | Claude Code 状态栏推送，见 [Claude 订阅额度接入](CLAUDE-USAGE.md) | 5 小时、7 天剩余 |
| Codex 用的 API 账户，例如中转站 | 账户的余额接口或查询链接 | 额度上限与剩余、余额、今日消费 |
| 大肥鱼账户，默认 DeepSeek 官方 | DeepSeek 余额接口与会话计费 | 余额、按会话估算的消费 |

## 额度账户

- **订阅账户**：Codex、Claude。有快照就有数据，没有时显示“等下次运行或回复后更新”。
- **API 账户**：一个地址加一个密钥。同地址同密钥只算一个账户，余额只查一次。账户保存在 `quota-accounts.json`：名称、地址、密钥放在哪（钥匙串里的引用、环境变量名，或沿用 Codex 配置里的密钥）、哪些 Codex provider 用它、余额怎么查、币种、每个模型每百万 token 的价格、是否隐藏，以及账本 id。文件里没有密钥。
- 一个 Codex provider 只属于一个账户。Codex 会话按日志里的 provider 名称归到账户；ChatGPT 登录的会话归 Codex 订阅，不会去查 OpenAI 的 API 余额。
- Codex 文件夹里各个 `*.toml` 声明的 provider（有 `base_url` 的）会自动成为账户，不用填配置文件路径；读不到它的密钥时，账户卡片请你在额度管理里填写。

账户里的额度有两种：

- **额度窗口**：有上限，到点重置。订阅的 5 小时、7 天窗口按百分比；API 查询返回的额度上限按金额，例如中转站的每周额度。每个窗口各自过期，重置后不再显示旧的比例；至少一个窗口有效，账户就有数据可看。
- **余额**：不重置，用完为止。满格取密钥的总额度；没有总额度时取**满格余额**，即上次充值以来观测到的最高余额，退款这类小幅上涨不算充值。

API 账户可以设一个**安全额度**：余额或剩余额度不低于它就算满格（100%），低于时按占它的比例显示。设了以后，进度条、▾ 浮层和额度提醒都按它计算，浮层里写明“安全额度”；清空后回到满格余额或额度上限。安全额度按账户的币种填写。

进度条：有额度窗口就显示窗口（订阅两条，API 一条），否则显示余额占满格的比例；不限额或还没有满格时只显示账户名。条形右边写着剩多少：订阅写剩余百分比，API 账户写剩余的额度或余额（跟随显示币种）。

## 当前额度

挂件显示最近有活动的账户：Codex 完成一轮（按订阅或所用的 provider 归属）、Claude 完成一次回复、你在会话里发出一条消息。主动闲聊和番茄钟提醒不算活动。在 ▾ 浮层里点“设为当前”后，一直保持到出现更晚的活动。活动时间和你的选择保存在 `quota-state.json`，重启后不变。

## 消耗速度

- 订阅窗口：按“已用比例 ÷ 窗口已过去的时间”推算到重置时会用掉多少；超过 100% 就说出预计用完的时间。窗口刚开始时（过去不到十分之一，或不到 15 分钟）不推算。
- 带上限的 API 额度和余额：按最近 7 个完整日里有记录的日均消费推算重置前够不够、还能用几天。最近都没有消费时说“近 N 天没有消费”。

## 大肥鱼账户

大肥鱼的所有模型请求都用这一个 API 账户：会话、主动闲聊、番茄钟提醒，以及以后的智能功能。默认是 DeepSeek 官方。会话设置里只选账户和模型，密钥在额度管理里填写；选了也给 Codex 用的账户时，两边共用额度。会话计费的余额与额度簿走同一个查询和缓存。

## 额度管理窗口

菜单、托盘和浮层里的“额度管理…”打开。标题栏可以切换金额显示的币种（与菜单里的“显示币种”同步）。

- **账户**：订阅部分有“读取本机 Codex 会话记录”的开关，以及一键“接入 Claude Code”/“移除接入”。每个 API 账户一张卡片：用途标签、额度或余额、消耗速度、密钥状态（缺少时可直接粘贴），以及“立即查询”“编辑”“隐藏”。编辑里改名称、密钥、币种、安全额度和按模型的价格；查询方式、查询链接、自定义 JSON 字段和 Codex provider 归属收在“高级”里。“添加 API 账户”填名称、地址和密钥，保存后立即查询。所有改动立即生效，不刷新页面。
- **记录**：每个账户一段，回答还剩多少、按这个速度够用多久、钱花在哪。API 账户有近 7 天每日消费的柱状图（共用账户在柱子里标出大肥鱼的部分）、今日 / 近 7 天 / 近 30 天金额、共用账户里 Codex 任务与大肥鱼各自的消费，以及可展开的明细。Codex 订阅列出最近几轮及每轮后剩余的额度。
- **提醒**：额度不足（任一窗口剩余低于设定比例；余额低于满格的设定比例，或低于各币种的设定金额）、今日消费（各币种账户合计超过设定金额）、完成提示（每轮花费气泡的开关与停留秒数，失败或取消时是否也提示）。

## 记录口径

- 每日消费：查询链接返回的 `daily_usage` 优先，其次是大肥鱼运行期间观测到的已用或余额变化。只给大肥鱼用的账户在没有观测的日子里，用会话计费的估算补上，并标为估算；第一次请求之前的日子算作未知，不当成零。
- 共用账户：当天总消费减去大肥鱼请求的估算，就是 Codex 任务的消费。Codex 一轮按同密钥余额差值记账时，若期间大肥鱼也用过这个账户，明细会写明那部分扣费也在里面。
- 明细：Codex 每轮写明“期间扣费”“估算”“待记账”或“金额未知”；大肥鱼的请求都是估算。token 数只出现在明细里。
- 金额统一保留两位小数，跟随显示币种；没有汇率时按账户自己的币种显示。

## 提醒

提醒由额度簿判断，以标准系统气泡弹出。额度或余额每跌破一次阈值只提醒一次，恢复到阈值以上后才会再提醒；查询失败的那段时间不会误判为恢复。今日消费每个币种每天最多提醒一次。设置保存在 `usage-settings.json` 的 `quotaAlerts`。

## 迁移

第一次运行时，额度簿从旧设置里收集已经在用的账户：`api-settings.json` 里的每个 Codex 配置来源、默认 Codex 配置（只有在它用 API 密钥而不是 ChatGPT 登录时），以及 `chat-settings.json` 里的会话地址和密钥（设为大肥鱼账户）。账户沿用原来的账本 id 和钥匙串引用，历史记录不搬家；`api-settings.json` 和 `chat-settings.json` 原样保留，回退到旧版本仍能用。旧版余额预警和今日预算按原币种迁为额度提醒；旧版菜单里手动选的 Codex / Claude 迁为“设为当前”。

## 接口

| 路由 | 说明 |
| --- | --- |
| `GET /api/quotas` | 全部账户、当前额度和最近的提醒；`?refresh=1` 先重新查询所有 API 账户 |
| `PUT /api/quotas/current` | `{ id }`，设为当前 |
| `GET /api/quota-records` | 记录页的数据 |
| `GET` / `POST /api/quota-accounts` | 账户列表（同时查找新的 Codex provider）/ 添加账户并查询 |
| `PUT /api/quota-accounts/:id`、`POST /api/quota-accounts/:id/query` | 修改账户（含密钥）/ 立即查询 |
| `PUT /api/quota-settings` | `{ monitorSessions }` |
| `GET` / `POST /api/claude/integration` | Claude Code 接入状态 / 接入、移除 |

响应里没有密钥。本地 IPC 通道只开放读取的 `/api/quotas`、`/api/quota-records`；MCP 的 `whale_balance` 读 `/api/quotas`，`whale_usage` 读 `/api/quota-records`，`whale_status` 附带全部账户。

## 代码

- `runtime/quota/windows.mjs`：额度窗口的唯一规则；`pace.mjs`：消耗速度；`alerts.mjs`：提醒判断；`records.mjs`：记录页数据。
- `runtime/quota/accounts.mjs`：账户存储、迁移、自动发现、密钥读写；`book.mjs`：额度簿，汇总账户、当前额度、提醒与记录。
- `desktop/ui/quota-presentation.js`：额度的文字与进度条（纯函数）；`quota-view.js`：挂件下方的进度条与 ▾ 浮层；`quota-manager.js`：额度管理窗口。

## 验证

`npm test`、`npm run check`、`npm run test:desktop`。测试只用临时目录和合成数据，不向 Codex、Claude 或任何真实账户发请求，也不读写真实的 Claude 设置。
